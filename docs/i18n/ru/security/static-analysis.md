# Статический анализ

Каждый контракт перед развёртыванием прогоняется через slither 0.11.6 и solhint, и каждое
срабатывание либо исправлено, либо объяснено здесь. Семь пулов являются семью развёртываниями
этих же трёх контрактов, поэтому один прогон покрывает их все. Эта страница является
объяснением. Сам прогон повторяем:

```bash
npm run lint -w @hearth/contracts
```

для solhint, который проходит без единого предупреждения на настроенном наборе правил в
`.solhint.json`, а для slither берётся обычная компиляция тех же исходников без плагина FHEVM
для Hardhat, потому что плагин переписывает `ZamaConfig.sol` во время компиляции, и slither
после этого уже не может сопоставить смещения в исходнике с файлом на диске. Обычная
компиляция использует те же настройки компилятора (0.8.27, оптимизатор на 800 прогонов,
cancun), поэтому байткод, который читает slither, является тем самым байткодом, который
выходит в бой.

## Прогон

slither проанализировал 46 контрактов 102 детекторами и сообщил о 88 результатах, 85 из них в
собственных контрактах Hearth. Ни один из них не является ошибкой. Они распадаются на пять
семейств, и у каждого семейства одна причина.

| Семейство | Количество | Серьёзность по версии slither | Почему это не находка |
| --- | --- | --- | --- |
| `unused-return` | 38 | Средняя | 36 из них являются `FHE.allow`, `FHE.allowThis`, `FHE.allowTransient` и `FHE.makePubliclyDecryptable`, которые возвращают полученный хендл, чтобы вызовы можно было соединять в цепочку. Игнорировать этот возврат является задокументированным способом использования в каждом примере Zama. Остальные два разобраны ниже. |
| `reentrancy-no-eth`, `reentrancy-benign`, `reentrancy-events` | 20 | Средняя и низкая | slither считает любую операцию `FHE.*` внешним вызовом, потому что каждая из них является вызовом в контракт сопроцессора. Эти вызовы несут хендлы шифротекста, а не управление, и внутри них не выполняется ни один пользовательский контракт. По-настоящему внешними вызовами являются токен и хранилище, оба зафиксированные при создании, а каждая функция, которая двигает ценность, помечена `nonReentrant` и пишет своё состояние до перевода. |
| `timestamp` и `incorrect-equality` | 18 | Низкая и средняя | Периоды намеренно определяются через `block.timestamp`, а строгие равенства сравнивают номера периодов и нулевые флаги, но никогда не балансы. Валидатор может сдвинуть метку времени на секунды против периодов в час или шесть часов, а это двигает вес вкладчика на столько же секунд из 3 600 или 21 600. |
| `uninitialized-local` | 8 | Средняя | Накопители и счётчики, которые намеренно начинаются с нулевого значения по умолчанию в Solidity: `offered`, `assigned`, `totalShares`, `processed`, `heavy`, `marked`, `cleared`. Переменной `harvestHandle` присваивается значение на каждом пути try/catch, который следует за её объявлением. |
| `calls-loop` | 1 | Низкая | `finalizeDraw` спрашивает у пула частоту сверок для каждого из трёх уровней. Цикл ограничен тремя итерациями, а пул является собственным пулом хранилища, заданным владельцем один раз. |

Два результата `unused-return`, которые не являются вызовами контроля доступа:

- `HearthVault._withdraw` игнорирует хендл, который возвращает `confidentialTransfer`. Перевод
  ERC-7984 переводит либо всю сумму, либо ничего, а хранилище уже ограничило сумму меньшим из
  того, что есть у вкладчика, и того, что есть у хранилища, в той же транзакции, поэтому
  переведённая сумма по построению равна запрошенной. Учёт был обновлён до вызова.
- `SponsoredYieldSource.sponsor` игнорирует то, что возвращает `wrap`. Спонсор здесь является
  доверенной стороной по определению, а то, что пул учитывает при закрытии, никогда не
  является собственной цифрой спонсора: это проверенная KMS сумма, которую источник
  действительно перевёл при сборе дохода.

## Чего slither не видит

slither рассуждает о потоке управления в открытом виде. Он не может определить, является ли
зашифрованное сравнение правильным сравнением, не потерян ли выданный доступ в списке
контроля доступа и не публикуется ли значение, которое публиковать не следует. Эти свойства
покрыты модульными тестами, тестами честности и инвариантов и исполненными скриптами атак из
[модели угроз](threat-model.md).
