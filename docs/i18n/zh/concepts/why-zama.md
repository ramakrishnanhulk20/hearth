# 为什么这必须用 Zama

对任何声称自己需要某项技术的项目，都该做这个测试：把那项技术删掉，看看产品还活不活得下来。
如果它照样能用，那项技术就只是装饰。

## 删掉加密，产品就不复存在

全同态加密，通常简称 FHE，指的是直接在加密数字上做算术，产出一个加密的答案，
全程从不解密输入。Zama 协议把这项能力带到了以太坊上：
一个 Solidity 合约可以对它读不懂的值做加法、比较和选择。

把它从 Hearth 里拿掉，剩下的是这些。

| Hearth 的组成部分 | 没有 FHE 会怎样 |
| --- | --- |
| 你的余额 | 一个公开数字。任何人都能给你的储蓄和中奖概率标价。 |
| 中奖判定 | 一次公开比较。结果在它运行的那一刻对所有人可见。 |
| 谁中了某一期 | 公开，因为落进某人余额的那笔入账是一个可见的数字。 |
| 随机种子 | 要么是一个有人能提前看到的公开数字，要么是一个有人能挑选的链下数字。 |
| 奖金入账 | 发给已识别中奖者的公开转账。 |

你得到的就是 PoolTogether。PoolTogether 已经存在了，它能用，而且跑了好些年。没有理由重造它。

Hearth 真正卖的，是 PoolTogether 给不了的东西：一种有奖储蓄，
你的余额、你的中奖概率和你的中奖记录只属于你，而开奖过程仍然可以被陌生人核查。
在一条透明链上，这两个性质是相互冲突的。
加密计算是唯一能化解这个冲突的东西，而 Zama 协议是今天以太坊上唯一做到这件事的地方。

这里没有折中版本。上面五行每一行都是核心承诺。把其中任何一行的加密拿掉，产品就在那一行上失效。

## 我们具体用到的部件

不是笼统的「构建在 Zama 上」。下面是清单，以及每一项为我们做了什么。

### 加密整数

`euint64` 用于金额和权重，`euint128` 用于资金池的总累加器，`ebool` 用于一次比较的结果。
每位储户的本金、中奖余额、权重和入账额都是其中之一，每个档位的结转额也是。
我们在它们上面执行的算术是 `FHE.add`、`FHE.sub`、乘以公开数字的 `FHE.mul`、
`FHE.min`、`FHE.gt`、`FHE.le`、`FHE.and` 和 `FHE.select`。

比较在这里干的活不止中奖判定。每期开奖有五次加密比较，
把资金池的总权重与它上次已知区间周围的那些 2 的幂做对比，
而离开加密世界的只有「五次里超过了几次」这个小计数。
这就是开奖如何拿到一个可以用来跑的公开规模，而总额本身从未变成一个数字。

`FHE.select` 值得单独说一句，因为正是它让整套设计成为可能。
它是一个条件为加密值的 if 语句：它返回两个加密值中的一个，而链上分辨不出是哪一个。
这就是一个中奖者和一个没中的人如何产生完全相同的交易。Hearth 里没有任何地方在秘密上分支。

`FHE.fromExternal` 接收一个用户在浏览器里构造的加密值和它的证明，
把它变成合约可以使用的值。这就是一笔存款金额如何端到端地以加密形式抵达。

### ERC-7984，机密代币标准

每个池的资产都是 Zama 的机密代币之一，它是套在普通 ERC-20 外面的 ERC-7984 包装合约：
cUSDC、cUSDT、cWETH、cBRON、cZAMA、ctGBP 或 cXAUt。它们里面的余额是加密值，不是公开数字。

存款通过 `confidentialTransferAndCall` 抵达，它在同一笔交易里转移一个加密金额并调用收款方的钩子。
金库的钩子拿到的是代币实际移动的那个金额，这就是金库记入现实而不是记入一个请求的方式。
支付则通过 `confidentialTransfer` 走反方向。

用标准代币而不是自己写一个，这件事很重要。这个领域好几个项目自己手搓了
「ERC-7984 风格」的代币。我们用的每一个都是 Zama 部署的代币，
所以储户的机密余额在 Hearth 之外也能用，而代币自身的行为不是我们可以按自己心意定义的东西。
这也意味着 Zama 发布一种新的机密代币，Hearth 当天就能在它上面开池，
七个池里有六个就是这么加进来的；同时也意味着，对于一种发行方把铸造权留给自己的代币，
Hearth 一个池都开不了。

### 加密随机数

`FHE.randEuint64()` 在 Zama 的协处理器内部、在网络 FHE 密钥之下，
从一个公开但没有那把密钥就毫无用处的种子生成一个随机数。
出来的是密文。没有人在它被创建的那一刻看到过它，我们没有，发出那笔交易的人也没有。

它必须在一笔交易内部生成，因为它会改变链上生成器的状态。
这就排除了用 `eth_call` 在链下预演一期开奖、看看自己会不会中的把戏，
也正是关闭一期开奖是一笔恰好只能成功一次的真实交易的原因。没人能把不喜欢的种子重摇一次。

### 访问控制列表

Zama 的链上 ACL 决定谁可以解密哪份密文。它是执行，不是政策：
对于调用者没有权限的句柄，中继器会拒绝这个请求。

Hearth 在它上面用了四个调用。`FHE.allowThis` 让一个值在后续交易里仍能被合约使用。
`FHE.allow` 授予储户对自己的本金、中奖余额、每期权重和每期入账额的永久读取权。
`FHE.allowTransient` 授予一笔交易时长内的访问权，
金库正是这样把一批评估的总额一次性授权给资金池，而从不给它常驻权限。
`FHE.makePubliclyDecryptable` 把一个值向所有人打开，而我们只在恰好六类值上使用它：
种子、给出区间的规模计数、非空标志、收割额、某个档位到期对账时的结转额，以及未足额计数器。
资金池的精确总权重被刻意排除在这份清单之外。

最后那个调用是单向且永久的。它是这套协议上一个合约能做的最有后果的一件事，
所以 Hearth 里对它的每一次使用都列在
[什么保持私密](../security/what-stays-private.md)里。

### EIP-712 用户解密

这是储户读自己数字的方式。他们签一条结构化的类型化消息，
这是一种能向签名者清楚展示自己在批准什么的签名标准，
然后 Zama 的中继器返回该储户有权限的那些值的明文。

这是一个链下请求。没有交易，没有 gas，没有痕迹。
这就是 Hearth 可以完全没有领奖函数的原因：得知自己中了奖不花一分钱，也不留下任何东西。
这个承诺的另一半是，评估同样无法瞄准你自己，
所以不存在任何一种只有中奖者才会发出的交易。

余额和中奖余额都可以由它们的拥有者解密。Hearth 还授予每期权重和每期入账额的权限，
这样储户就能用自己的输入去验证这一期的算术，而不是被要求去信任它。

### KMS 签名的公开解密

反方向。一个合约把某个值标记为可公开解密，任何人向中继器索取明文，
中继器返回时带上密钥管理服务的签名，那是持有网络解密密钥的那个群体。
合约随后在链上用 `FHE.checkSignatures` 验证那个签名，才会依据这个数字行事。

这就是把「我们说种子是 12345」变成一个合约自己不见证明就不肯接受的数字。
Hearth 每期开奖在发奖时用它一次，同时处理种子、规模计数、非空标志和收割额，
之后每当某个档位到期对账时再用一次处理它的结转额，在 Sepolia 上就是每个档位每期都用。
每一份证明都按固定顺序与它的句柄绑定，所以什么都不能被打乱，
也不能被重放到另一期开奖或另一个档位上。

## 一位储户实际在信任什么

把这件事说清楚，就是本页的意义。

- **Zama 协议**，信任它在密文上正确计算，并且只解密被标记为可解密的东西。
  合约据以行事的每一次解密都带着一份在链上验证过的证明。
  这与 Zama 自己的机密金库所记录的信任边界是同一个。
- **机密代币包装合约**，那些是 Zama 的合约而不是我们的，而且可由其拥有者升级。见
  [什么保持私密](../security/what-stays-private.md)的代币层一节。
- **Hearth 自己的合约**，它们一经部署就不可变，没有代理，没有升级路径。
  拥有者剩下的权力很窄，列在[威胁模型](../security/threat-model.md)里：
  一个能停掉存款和开奖关闭、但永远停不掉提取和评估的暂停开关，一个收益来源设置器，
  一条碰不到储户余额的外来代币救援路径，以及禁用了放弃的两步所有权转移。

这份清单上没有一项是「我们请你相信的某个人」。
