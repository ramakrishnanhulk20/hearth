# 什么保持私密

关于机密性有三件事要紧：什么保持加密、开奖是否可证明公平且按存款加权、每一处泄漏是否都被点名。
本页回答第一件和第三件。我们的立场是：自己把每一道接缝都点出来，比一句没人能核查的主张更有价值。

这里写的一切都是针对一个池子的，而 Hearth 跑着七个，每种机密代币一个。
它们不共享任何东西，所以每个池的匿名集只有它自己的储户，
一个有三位储户的池子不会因为另一个池有三十位而变得更安全。

## 那张表

| 数值 | 状态 | 谁能读 |
| --- | --- | --- |
| 你的本金 | 加密 | 只有你，通过 EIP-712 签名 |
| 你未领取的中奖余额 | 加密 | 只有你 |
| 你的每期时间加权权重 | 加密 | 只有你 |
| 你的每期入账额，也就是你有没有中奖 | 加密 | 只有你 |
| 你存入的金额 | 端到端加密 | 只有你 |
| 你提取的金额 | 端到端加密 | 只有你 |
| **资金池某周期的总权重** | **加密，从不公布** | **没有人** |
| 每个档位两次对账之间的结转额 | 加密 | 没有人 |
| 池子总额所落入的区间，一个 2 的幂 | 周期结束后公开 | 所有人 |
| 该周期究竟有没有人持有余额 | 周期结束后公开 | 所有人 |
| 每期的随机种子 | 周期结束后公开 | 所有人 |
| 每期收割到的收益 | 周期结束后公开 | 所有人 |
| 每个档位的奖金金额和拿出来的明文流动性 | 关闭起公开 | 所有人 |
| 高频档派出了多少份奖 | 一期之后公开 | 所有人 |
| 中档派出了多少份奖 | 一期之后公开 | 所有人 |
| 大奖档派出了多少份奖 | 一期之后公开 | 所有人 |
| 储户地址名单 | 公开 | 所有人 |
| 你何时存入、提取或被评估，以及在哪一批 | 公开 | 所有人 |
| 未足额计数器 | 终结时公开 | 所有人 |
| 赞助金额和滴出速率 | 公开 | 所有人 |
| 你包装进机密代币、或从中解包装出来的金额 | 公开 | 所有人 |
| 任何地址在任何档位必须超过的每一个阈值 | 可公开计算 | 所有人 |

这张表有两种读法。左边那列秘密，恰好就是每个人各自的信息，
外加两个原来是每个人信息乔装打扮的池级总额。右边那列公开事实，
恰好是一个外人核查开奖是否诚实所需要的东西。这个划分就是设计本身。

## 一个观察者能推出什么，推不出什么

一个有完整归档节点和无限耐心的观察者可以建出：

- 完整的储户名单，以及每个人操作所在的确切区块。
- 每一期的种子、区间、收割额和奖金金额，以及每个档位的中奖数量，在它所属那一期之后一期。
- 每个地址必须超过的每一个阈值。他们真的可以算出你的整架梯子。
- 资金池所持机密代币总量的加密句柄，而他们读不懂它。

他们拿不到的：

- 任何时刻的任何个人余额。
- 任何个人的权重，因而也拿不到任何人的中奖概率。
- 哪些地址中了哪一期，或者谁被付了多少。
- 资金池的精确总权重，只有它上方的那个 2 的幂。

这两份清单之间的落差，就是 Hearth 所卖的东西。本页剩下的部分，
是对这个落差在哪里变窄的诚实交代。

## 规则 1：区间，以及我们移除的那个泄漏

直到 2026 年 9 月 3 日之前，这套设计在每期开奖时公布资金池精确的时间加权余额总额 `W`，
理由是公布它才让开奖可验证。一次评审证明那个理由代价太高。

用评审者的说法，泄漏是这样的。对任何已关闭的周期 `p`，
`W_p = B * L + 每个动作的 D_i * (periodEnd(p) - t_i) 之和`，其中 `B` 是带进该周期的总本金，
`D_i` 是每个动作带来的有符号变化。`B`、`L`、`periodEnd(p)` 和每一个 `t_i` 都是公开的，
因为存入和提取事件带着时间戳。所以 **一位在某周期内唯一动过钱的储户，
其金额可以从两个公布的总额和他自己那笔交易的公开时间戳中还原出来。**
不是框住范围，是精确还原，余数为零。而且数据越多它越糟，不是越好：
每个已关闭的周期多一条方程，每个动作多一个未知数，这条链锚定在零上，
而事件写明了谁在何时操作，所以两个安静周期之间的两位动钱者同样会被精确还原。

那个泄漏没有了，因为它需要的那个数字不再被公布。金库现在公布的是区间：
刚好不小于 `W` 的那个 2 的幂，写作 `M`。每期五次加密比较追踪 `W` 相对上一期区间的位置，
只有它们加起来的那个小计数会被解密。
在两次跨越 2 的幂之间，相邻各期公布的是同一个数字，做差得零。

剩下的是同一件事一个小得多的版本。

- **一位储户。** 公布的区间就是那位储户的权重，误差在两倍以内。
- **两位储户。** 每个人都能减掉自己的权重，把对方框住，同样在两倍以内。
- **三位或更多。** 任何与该区间相容的划分都有可能，而且这个集合随着每多一位储户而增大。

只要池子的储户少于三位，应用就会在每个屏幕上方声明这一点。
Zama 自己的文档对他们的批处理器讲了同样的道理，用的话也一样：
「一个值的和就是那个值。」区间是这句话的一个更弱版本，而不是对它的逃脱。

## 规则 2：一个观察者能锁定的余额，在开奖上毫无隐私可言

这是本页最尖锐的一句话，所以它单独成为一条规则。

中奖判定是一个函数，输入只有一个秘密（你的权重），其余全是公开数据。
阈值按设计就是公开的，因为它们正是让开奖可核查的东西。所以 **任何能锁定你余额的人，
都能在完全不解密的情况下算出你在每一期每一个档位的输赢**，而且此后每一期也都算得出，
因为中奖余额待在一个从不进入中奖概率计算的独立余额里。

余额被锁定的通常方式是规则 3 里那道包装接缝：把一种公开代币包装成它的机密形式是一次公开移动，
所以一位储户如果包装之后隔几秒就存入同样的金额，就等于公布了自己的存款额。
从那一刻起，他的开奖结果就是公开算术。

哪怕是一个宽松的边界也咬得动。一个只掌握你余额上界的观察者，
在任何阈值高于那个上界的档位里，都能证明你必定没中。

应用对此做了什么：把封装和存入保持为「存入」页面上两个独立的步骤，
并在封装那一步用一段话告诉你，用一个整数，好让一次封装是一个区间而不是一笔精确的存款；
在你自己挑的时间点封装；之后再存入其中一部分，
这样一笔存款就是从一堆组成不明的积累里取出来的。
而任何合约改动都做不到的，是让阈值变成私密的，因为一个私密的阈值就是一次无法核查的开奖。

## 规则 3：包装接缝，两个方向

把一种公开代币变成它的机密形式是一次公开的 ERC-20 移动。这个金额会出现在
包装合约的 `Wrap` 事件里、出现在底层代币的 `Transfer` 里，
还会第三次出现在协处理器加密那个明文的记录里。没有机密的方式可以转换一种公开代币。

我们在自己更早那版部署上测量过这种关联。扫描 Sepolia 区块 11528000 到 11618500，
五笔存入里有三笔紧跟在同一地址恰好 100 USDC 的公开包装之后两到四个区块。
任何读公开日志的人都能把这三笔存入定价为 100 USDC，而没有攻破任何一项密码学保证。
Zama 为他们的批处理器记录了同样的效应，称之为封装与加入的关联。

解包装同样会公布一个金额，而且是两次解包装调用中的第一次公布的，
所以一次从未确认完成的解包装照样会泄漏。由此还得到第二项被点名的披露：
**对任何全额包装进来、又全额解包装出去的地址来说，累计中奖所得会成为一个公开的下界。**
对于一个在那种机密代币上唯一交易对手就是 Hearth 的地址来说，
公开的解包装总额减去公开的包装总额，恰好是终身已提取的中奖所得，
再减去该地址仍持有的本金和机密余额。这两者都是隐藏的且非负，
所以这个差值永远是一个下界，而一旦该地址把钱全部搬空，它就成了精确值。

解包装到一个全新地址没有用，因为发往那个地址的机密转账本身就是那条关联。

Hearth 做了什么：分开的步骤，在「存入」的封装那一步加警告，
在那一步和「提取」页面「换回普通 USDC」标签页上各写一行，告诉你转一个整数，
以及建议留一笔常备的机密余额在里面。无论如何，金额都由你自己输入；
应用不提供一组固定面额。Hearth 做不到的：把这些去掉，一点都去不掉。

## 规则 4：公布的中奖数量是一次缓慢的测量

每一次对账都会公布某个档位派出了多少份奖。因为每位储户的阈值都是公开的，
那个数量就是一条硬约束，形式是「这些储户里有多少人的权重超过了他们各自公开的阈值」。
它只携带几个比特，但它是一次真实的测量，而且它会累积。

**一个跨越许多期都不变的余额，会被这些数量逐步收窄。**
一位做了存入或提取的储户，会重置自己的未知量，让收窄从头开始。

有两件事限制着这个速率。这些数量是粗颗粒的：披露的从来不会细过整数份的奖项。
而且阈值不是攻击者可以选的，因为种子是在协处理器内部摇出来的，
只在它所属周期关闭之后才揭示，所以没人能对某个被怀疑的余额发起有针对性的查询。

第三个抑制手段本来是有的，而本次部署有意放弃了它。
`reconcileEvery[t]` 设定一个档位两次公布结转额之间要过多少期。
把它调高就是每段跨度公布一个数量，而不是每期一个，
于是一份大奖会被归因到那整段跨度里所有符合条件的人。
它的代价是大奖本身：一次关闭会把一个档位全部的公开流动性移进本期开奖，
而这笔钱只有在对账时才回来，所以在节奏为 24 的情况下，
24 期里有 23 期大奖档的公开流动性只是一期的收割份额，公布的奖金按那个定大小，
而累积起来的奖池只在对账那一期才出现在明面上。这笔钱全程都在加密结转额里被拿出来发、可以被赢走。
只是没人能看见它。

所以三个档位全都跑在 `reconcileEvery = 1` 上。奖池在公开处累积，
每个档位的数量在一期之后变公开，而上面说的那种测量以每档位每期一个数量的全速运行。
在大奖档上，这意味着一次派奖指向的是那一期里符合条件的储户，大约占池子的四个百分点，
而不是一整天的人。这是一项已披露的残余风险，不是一项已缓解的，它是局限 14。
节奏依然是一个构造函数参数，所以一个宁愿要更慢测量而不要可见奖池的部署可以这么做。

## 规则 5：代币层是 Zama 的，不是我们的

每个池的资产都是 Zama 的机密代币之一。这是有意的，
也意味着代币自身的权力适用于经过 Hearth 的资金，逐池适用：七个包装合约，每一个上的权力相同。
把它们点名如下：

Sepolia 上那个合约是一个可升级代理背后的 `ConfidentialWrapper`，由 Zama 拥有，
两步所有权转移，放弃已禁用。在 2026 年 9 月 2 日阅读它已验证的源码，
得到三个对隐私要紧的事实：

1. **观察者，可追溯生效。** 拥有者可以调用 `addObserver(address)`，
   这会授予该地址对代币合约持有权限的每一个句柄的通配符用户解密权。
   这覆盖每一笔存款金额、每一笔提取支付，以及资金池发给金库的每一批奖金拨付金额。
   要紧的词是「可追溯」：一个在未来任何时刻被任命的观察者，
   都能解密已经在链上的金额，所以「盯着 `ObserverAdded` 然后退出」不是一种防御。
   2026 年 9 月 2 日的链上状态：`observerCount()` 是 0，`observers()` 为空。
2. **拒绝名单和暂停。** 拥有者可以封禁一个地址，使它无法存入、提取或解包装，
   因为这三件事每一件都是一次以该地址为一方的代币更新。
   存在一个 pauser 角色；线上它被设为零地址，所以暂停目前是禁用的。
3. **可升级性。** 实现合约可以被它的拥有者替换，
   所以代币的行为，包括它如何处理自己有权限的那些句柄，可能在我们脚下改变。

注意第 1 条的确切范围。Hearth 里没有针对每位储户的奖金转账，
所以没有针对每位中奖者的支付供观察者读取。在代币层移动的，
是每批评估一次的拨付转账，从资金池到金库，携带的是记给该批次里所有人的总额。
一个只有一位储户的批次，会让那个总额成为该储户的确切奖金，
而在实际运行的五位储户池子里，批次大小为 4 时每一次遍历都以一个只有一位储户的批次收尾。
`evaluate` 无需许可，并且从调用者那里取批次大小，所以没法强制一个最小批次。
[局限 7](../limitations.md) 把它记为一项被接受的残余风险，并指出了合约侧的修法。

代币层的观察者拿不到的，是 Hearth 自己的账本。你的本金、你的中奖余额、你的权重和你的入账额
都存在金库的存储里，而代币对它们中任何一个都没有访问控制权限。
我们在上一版部署上验证过这一点：代币地址在一位存款人的中奖余额和本金句柄上查询权限返回 false，
而该存款人和资金池返回 true。

所以诚实的说法是：使用 Hearth，你把经过它的那些金额托付给了 Zama 的包装合约，
和任何一个 ERC-7984 应用一样。你没有把自己的头寸托付给它。

替代方案是自己写一个机密代币，这个领域里好几个项目就是这么做的。
那是拿一个已知的、经过审计的、由 Zama 运营的合约，去换一个由我们自己打分的合约。
我们宁愿把真实的信任边界写清楚，也不愿制造一个看起来更小的。

## 规则 6：评估不是破绽，而且没人能选择顺序

`evaluate(drawId, count)` 接受的是一个数字，不是一份地址清单。
金库从该期种子推导出的起点开始，按名单顺序遍历储户名单，而调用者只决定往前推进多远。
一位想要自己结果的储户，推进的是 keeper 也在推进的那同一条遍历。

这一下关掉了两件事。

它关掉了自我评估这个破绽。在更早的版本里，评估接受一份地址清单，
所以一位储户可以从公开输入算出自己的结果，然后只在自己中了奖时才花钱去被评估。
发出那笔交易本来会是一个和领奖函数一样响亮的中奖信号。现在不存在只有中奖者才会发的交易。

它也关掉了顺序这根杠杆。当一个档位超额派奖并耗尽时，遍历最后走到谁，谁就拿不足。
那个顺序由种子固定，所以没人能用 gas 买一个更好的位置，
而且起点每期都在移动，所以没有哪个地址会系统性地排在最后。
公平性上的后果描述在
[奖金与档位](../concepts/prizes-and-tiers.md)里，它是局限 11。

一期里被评估的每位储户，无论中没中奖，都得到相同形状的相同写入，
因为支付走的是加密选择而不是分支。一位储户落在哪一批、在批里的什么位置，都是公开的，
而且关于他的结果什么都说明不了。

## 规则 7：行为层面的残余风险

Hearth 没有领奖交易，所以没有一种中奖者形状的动作可供盯梢。
得知自己中了奖是一次什么都不碰的链下签名，而应用里那个带金额的领奖按钮，
发出的是一笔和其他任何提取都一样的普通提取。

残余风险在于你接下来做什么。一位储户如果每次中奖之后立刻提取、其他时候从不提取，
就会随时间给观察者递上一条统计线索。它很弱，要许多期才建得起来，而且完全在储户自己的掌控中。
缓解手段是行为上的，不是密码学上的：按你自己的节奏提取，或者让中奖余额攒着。

我们把这条写出来，是因为另一个选择，也就是声称链上行为什么都不暴露，
在这一类的每一种设计里都是假的。这个领域里那些移除了领奖函数的项目得出了同样的结论，
并且把它写了下来。我们也一样。

## 本页没有覆盖什么

它没有讲攻击者和他们的动机，那是
[威胁模型](threat-model.md)。它没有讲怎么自己核查一期开奖，那是
[随机性与可验证性](randomness-and-verification.md)。它也不对网络层隐私做任何主张：
你连接时用的 IP 地址、你用的 RPC 服务商、你发出的中继器请求，都在链之外，也在这份分析之外。
