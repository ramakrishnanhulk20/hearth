# நிலையான பகுப்பாய்வு

ஒவ்வொரு டெப்ளாய்மென்ட்டுக்கும் முன் ஒவ்வொரு ஒப்பந்தமும் slither 0.11.6 மற்றும் solhint வழியாக
இயக்கப்படுகிறது, கண்டறியப்படும் ஒவ்வொன்றும் சரிசெய்யப்படுகிறது அல்லது இங்கே விளக்கப்படுகிறது. ஏழு
பூல்களும் இதே மூன்று ஒப்பந்தங்களின் ஏழு டெப்ளாய்மென்ட்கள், எனவே ஒரே ஓட்டம் அவை அனைத்தையும்
உள்ளடக்குகிறது. இந்தப் பக்கம் விளக்கம். கச்சா ஓட்டத்தை மீண்டும் நடத்தலாம்:

```bash
npm run lint -w @hearth/contracts
```

இது solhint க்கு, `.solhint.json` இல் இருக்கும் சரிசெய்யப்பட்ட விதித் தொகுப்பில் அது பூஜ்ஜிய
எச்சரிக்கைகளுடன் வெற்றி பெறுகிறது. slither க்கு, FHEVM Hardhat ப்ளக்இன் இல்லாமல் அதே மூலங்களின் ஒரு
சாதாரணத் தொகுப்பு, ஏனெனில் ப்ளக்இன் தொகுக்கும் நேரத்தில் `ZamaConfig.sol` ஐ மீண்டும் எழுதுகிறது,
அதன்பிறகு வட்டில் இருக்கும் கோப்புக்கு மூல இடங்களை slither ஆல் பொருத்த முடிவதில்லை. அந்தச் சாதாரணத்
தொகுப்பு அதே தொகுப்பான் அமைப்புகளையே (0.8.27, ஆப்டிமைசர் 800 ஓட்டங்களில், cancun) பயன்படுத்துகிறது,
எனவே slither படிக்கும் பைட்கோடே அனுப்பப்படும் பைட்கோடு.

## ஓட்டம்

slither 46 ஒப்பந்தங்களை 102 கண்டுபிடிப்பான்களுடன் பகுப்பாய்வு செய்து 88 முடிவுகளைத் தெரிவித்தது, அவற்றில்
85 Hearth இன் சொந்த ஒப்பந்தங்களில். எதுவும் ஒரு பிழை அல்ல. அவை ஐந்து குடும்பங்களாக விழுகின்றன, ஒவ்வொரு
குடும்பத்துக்கும் ஒரே காரணம்.

| `timestamp` மற்றும் `incorrect-equality` | 18 | குறைவும் நடுத்தரமும் | காலகட்டங்கள் வேண்டுமென்றே `block.timestamp` ஆல் வரையறுக்கப்படுகின்றன, கண்டிப்பான சமன்பாடுகள் காலகட்ட எண்களையும் பூஜ்ஜியக் கொடிகளையும் ஒப்பிடுகின்றன, இருப்புகளை ஒருபோதும் அல்ல. ஒரு வேலிடேட்டர் ஒரு நேர முத்திரையை சில வினாடிகள் நகர்த்த முடியும், ஒரு மணி நேர அல்லது ஆறு மணி நேரக் காலகட்டங்களுக்கு எதிராக அது ஒரு சேமிப்பாளரின் எடையை 3,600 அல்லது 21,600 இல் அத்தனை வினாடிகள் நகர்த்தும். |

அணுகல் கட்டுப்பாட்டு அழைப்புகள் அல்லாத இரு `unused-return` முடிவுகள்:

- `confidentialTransfer` திருப்பும் ஹேண்டிலை `HearthVault._withdraw` புறக்கணிக்கிறது. ஓர் ERC-7984
  பரிமாற்றம் முழுத் தொகையை நகர்த்தும் அல்லது எதையும் நகர்த்தாது, சேமிப்பாளர் வைத்திருப்பதிலும் வால்ட்
  வைத்திருப்பதிலும் எது சிறியதோ அதற்குள் அதே பரிவர்த்தனையில் வால்ட் ஏற்கெனவே தொகையை அடக்கியிருக்கிறது,
  எனவே பரிமாற்றப்பட்ட தொகை கட்டமைப்பின்படியே கேட்கப்பட்ட தொகை. அழைப்புக்கு முன்பே கணக்கேடு
  புதுப்பிக்கப்பட்டது.
- `wrap` திருப்புவதை `SponsoredYieldSource.sponsor` புறக்கணிக்கிறது. இங்கே நிதியுதவியாளர் வரையறையின்படியே
  நம்பப்படும் தரப்பு, ஒரு மூடுதலில் பூல் பதிவு செய்வது ஒருபோதும் நிதியுதவியாளரின் சொந்த எண் அல்ல,
  அறுவடையின்போது மூலம் உண்மையில் பரிமாற்றிய, KMS சரிபார்த்த தொகை.

## slither ஆல் பார்க்க முடியாதவை

slither வெளிப்படைக் கட்டுப்பாட்டு ஓட்டத்தைப் பற்றியே சிந்திக்கிறது. ஒரு மறையாக்கப்பட்ட ஒப்பீடு சரியான
ஒப்பீடா, ஓர் அணுகல் கட்டுப்பாட்டுப் பட்டியல் அனுமதி விடுபட்டிருக்கிறதா, வெளியிடப்படக் கூடாத ஒரு மதிப்பு
வெளியிடப்படுகிறதா என்பதை அதனால் சொல்ல முடியாது. அந்தப் பண்புகளை அலகுச் சோதனைகளும், நியாய மற்றும் மாறிலிச்
சோதனைகளும், [அச்சுறுத்தல் மாதிரி](threat-model.md) இல் இருக்கும் நடத்தப்பட்ட தாக்குதல் ஸ்கிரிப்ட்களும்
உள்ளடக்குகின்றன.
