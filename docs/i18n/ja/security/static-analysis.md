# 静的解析

すべてのコントラクトは、デプロイの前に slither 0.11.6 と solhint を通し、すべての指摘は修正するか、ここで説明します。7 つの
プールは同じ 3 つのコントラクトの 7 回のデプロイなので、1 回の実行で全部をカバーします。このページはその説明です。生の実行は
再現できます。

```bash
npm run lint -w @hearth/contracts
```

solhint はこれで、`.solhint.json` の調整済みルールセットに対して警告ゼロで通ります。slither については、FHEVM の Hardhat
プラグインを外した同じソースの素のコンパイルを使います。プラグインはコンパイル時に `ZamaConfig.sol` を書き換えるので、slither が
ソースのオフセットをディスク上のファイルに対応付けられなくなるからです。素のコンパイルはまったく同じコンパイラ設定（0.8.27、
オプティマイザ 800 runs、cancun）を使うので、slither が読むバイトコードは実際に出荷されるバイトコードです。

## 実行結果

slither は 102 個の検出器で 46 のコントラクトを解析し、88 件を報告しました。うち 85 件が Hearth 自身のコントラクトです。バグは
1 つもありません。5 つの系統に分かれ、各系統に理由が 1 つずつあります。

| 系統 | 件数 | slither が付けた深刻度 | なぜ指摘に当たらないか |
| --- | --- | --- | --- |
| `unused-return` | 38 | Medium | うち 36 件は `FHE.allow`、`FHE.allowThis`、`FHE.allowTransient`、`FHE.makePubliclyDecryptable` で、呼び出しを連ねられるよう渡されたハンドルを返します。その戻り値を無視するのは Zama のすべての例で示された使い方です。残り 2 件は下記のとおりです。 |
| `reentrancy-no-eth`、`reentrancy-benign`、`reentrancy-events` | 20 | Medium と Low | slither はすべての `FHE.*` 操作を外部呼び出しとして扱います。それぞれがコプロセッサのコントラクトへの呼び出しだからです。それらの呼び出しが運ぶのは暗号文ハンドルであって制御ではなく、その内部でユーザーのコントラクトが動くことはありません。本当に外部なのはトークンとボールトで、どちらも構築時に固定されており、価値を動かすすべての関数は `nonReentrant` で、送金の前に状態を書きます。 |
| `timestamp` と `incorrect-equality` | 18 | Low と Medium | 期間は意図的に `block.timestamp` で定義されており、厳密な等価比較が比べているのは期間番号とゼロのフラグであって、残高ではありません。バリデータはタイムスタンプを数秒ずらせますが、期間が 1 時間や 6 時間なら、それは預入者のウェイトを 3,600 秒または 21,600 秒のうちの数秒ぶん動かすだけです。 |
| `uninitialized-local` | 8 | Medium | 意図して Solidity のゼロ既定値から始まる累計器とカウンタです。`offered`、`assigned`、`totalShares`、`processed`、`heavy`、`marked`、`cleared` です。`harvestHandle` は、その宣言に続く try/catch のすべての経路で代入されます。 |
| `calls-loop` | 1 | Low | `finalizeDraw` が 3 つのティアそれぞれの精算頻度をプールに問い合わせます。ループは 3 で有界であり、そのプールはボールト自身のもので、オーナーが一度だけ設定します。 |

アクセス制御の呼び出しではない 2 件の `unused-return` は次のとおりです。

- `HearthVault._withdraw` は `confidentialTransfer` が返すハンドルを無視します。ERC-7984 の送金は全額動くか何も動かないかの
  どちらかであり、ボールトは同じトランザクション内で、預入者の保有額とボールトの保有額の小さいほうにすでに金額を丸めているので、
  送金された額は構成上、要求した額です。帳簿はその呼び出しの前に更新されています。
- `SponsoredYieldSource.sponsor` は `wrap` の戻り値を無視します。ここではスポンサーが定義上の信頼された当事者であり、プールが
  クローズで計上するのはスポンサー自身の数値ではなく、ハーベストでソースが実際に送金した KMS 検証済みの額です。

## slither に見えないもの

slither は平文の制御フローについて推論します。ある暗号化された比較が正しい比較かどうか、アクセス制御リストの付与が抜けていないか、
公開すべきでない値が公開されていないかは判断できません。それらの性質は、単体テスト、公平性と不変条件のテスト、そして
[脅威モデル](threat-model.md)にある実行済みの攻撃スクリプトがカバーします。

## 依存関係の監査

リポジトリのルートでの `npm audit --omit=dev` は、2026 年 9 月 6 日時点で 2 件を報告します。どちらも `axios` に
あり、どちらもアプリが実行することのないコードです。

- コントラクトのパッケージにある、`hardhat-deploy@0.11.45` 配下の `axios@0.21.4`。これはオペレーターのマシンで
  動くデプロイ用の道具で、バンドルに載って出荷されることはありません。`hardhat-deploy` 0.11 は 0.21 系に固定して
  いるので、直す方法はデプロイツールのメジャーアップグレードだけであり、それはこのリポジトリが依存している
  デプロイ記録を変えてしまいます。
- `@wagmi/connectors` が WalletConnect のコネクタとともに引き込む `@coinbase/cdp-sdk` 配下の `axios`。Hearth は
  axios を import しませんし、Coinbase の SDK を呼ぶこともありません。これらの勧告が扱うのは Node における
  サーバー側のプロキシ処理とリクエストフォージェリであって、ブラウザのバンドルではありません。`npm audit fix` は
  入れ子になった写しを範囲の外に出すのではなく、別の脆弱なリリースに移すだけなので、lockfile が記録したままに
  してあります。

web パッケージ単体では、コネクタを外せば監査はクリーンです。9 月 3 日の指摘ゼロという数字はそうやって出しました。
