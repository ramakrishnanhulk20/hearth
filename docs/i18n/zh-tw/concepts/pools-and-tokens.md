# 資金池與代幣

Hearth 不是一個池。它是七個池，Zama 在 Sepolia 位址表上的每一種機密代幣各一個，每一個都有自己的
`HearthVault`、自己的 `HearthPrizePool` 和自己的 `SponsoredYieldSource`，也有自己的存戶、自己的
獎金和自己的 keeper。

這些合約是同一份程式碼，用不同的建構子參數部署了七次。鏈上什麼都不共用：沒有註冊表、沒有路由器、
沒有共用餘額。WETH 池的存戶看不到、碰不到 USDC 池，也不會被它影響，而某一種代幣上暫停的金庫或
卡住的 keeper，不會妨礙其他六個繼續跑。

## 為什麼是六小時，而不是七個池都一小時

因為 gas。在一個五位存戶的池上，一次抽獎在 Sepolia 實測收據上是 `8,456,388` gas：一次截止、一次
開獎、兩批評估、一次定案，加上每個層級各一次對帳。以 1 gwei 計，那是 `0.0085 ETH`。七個池都每小時
抽一次，一天就是 168 次抽獎，約 `1.43 ETH`，靠公開水龍頭撐不過一個評審期。十位存戶的池一次抽獎是
`12,582,923` gas，而且會隨人數繼續長。

所以後來部署的六個池每六小時抽一次。那是每個池一天四次，七個池加起來一天約 `0.41 ETH`，而不是
`1.43`，而一天四次仍然夠密集，訪客在單次造訪內就看得到一次落地。USDC 池維持它每小時的時鐘，也
維持隨之而來的那些歷史紀錄。

中獎機率是依各池自己的期別設定的，不是硬套過來的，所以兩種時鐘下產品的手感一樣：

| 層級 | 每小時的池（`usdc`） | 六小時的池 |
| --- | --- | --- |
| 頭獎 | 數量 1、機率 24 分之 1、份額 40 | 數量 1、機率 4 分之 1、份額 40 |
| 中型獎 | 數量 1、機率 6 分之 1、份額 20 | 數量 1、機率 2 分之 1、份額 20 |
| 常態獎 | 數量 4、機率 1 分之 1、份額 40 | 數量 4、機率 1 分之 1、份額 40 |

所以每一個池的頭獎大約一天派出一次。兩種時鐘唯一有差的是中型獎層級：每小時的池大約一天四次，
六小時的池大約一天兩次，因為把機率減半，還補不回抽獎次數只剩六分之一。每個池的每個層級都每期
對帳，理由見[獎金與層級](prizes-and-tiers.md)。

## 小數位數，以及一個金額代表什麼

Zama Sepolia 位址表上的每一個機密包裝器都讀作六位小數，不管底下的公開代幣是幾位，因為包裝器把
自己封在六位，把差額算進它的 `rate()`。機密 WETH 是最清楚的例子：它的底層有 18 位小數，所以包裝器
的 `rate()` 是一兆，包裝器裡的一個基本單位等於公開代幣的一兆個基本單位。

`packages/contracts/hearth.config.ts` 裡的每一個金額都是以包裝器的基本單位計，而部署腳本和各項
任務在碰公開代幣之前，會先乘上它們從鏈上讀到的 rate。這不是小細節。我們自己的稽核就抓到過一個
bug：某個池記的是呼叫者傳進來的金額，而不是包裝器實際鑄出的金額，在一個 18 位小數的代幣上，這會
把獎金放大一兆倍。見[收益來源](yield-source.md)。

## 每個池預先放了什麼

`hearth:seed --token <slug>` 會贊助收益來源，並放進五位示範存戶，取自帳戶索引 2 到 6，好讓第一位
訪客一進來就看到有人的池。各代幣的金額不同，因為池子得看起來像它持有的那種資產：1,200 顆美元
穩定幣和 0.6 顆以太幣，是同一種規模的存戶。

| 資金池 | 五筆示範存款 | 贊助金 | 釋出的獎金 |
| --- | --- | --- | --- |
| `usdc` | 1,200 / 600 / 300 / 150 / 75 | 10,000 USDC | 每小時 20 USDC，所以每期 19.998 |
| `usdt` | 1,200 / 600 / 300 / 150 / 75 | 10,000 USDT | 每小時 20 USDT，所以每期 119.98 |
| `weth` | 0.6 / 0.3 / 0.15 / 0.075 / 0.04 | 5 WETH | 每小時 0.01 WETH，無條件捨去後每期 0.0432 |
| `bron` | 2,000 / 1,000 / 500 / 250 / 125 | 15,000 BRON | 每小時 30 BRON，所以每期 179.99 |
| `zama` | 2,000 / 1,000 / 500 / 250 / 125 | 15,000 ZAMA | 每小時 30 ZAMA，所以每期 179.99 |
| `tgbp` | 1,000 / 500 / 250 / 125 / 60 | 8,000 tGBP | 每小時 16 tGBP，所以每期 95.99 |
| `xaut` | 0.4 / 0.2 / 0.1 / 0.05 / 0.025 | 3 XAUt | 每小時 0.006 XAUt，無條件捨去後每期 0.0216 |

一個來源的速率是每秒整數個基本單位，所以最小的兩個速率會被無條件捨去：每小時 0.01 WETH 是每秒
2.77 個基本單位，實際釋出 2；每小時 0.006 XAUt 是 1.67，實際釋出 1。每筆贊助金的規模都夠撐超過
八十期，也就是二十天以上，所以評審期間沒有人需要幫池子補錢。

## Hearth 拒收的那一種代幣

Zama 在 Sepolia 上也發行了一個非 mock 的 **Confidential tGBP**，位址
`0x167DC962808B32CFFFc7e14B5018c0bE06A3A208`，底下的公開代幣是
`0xf6Ef9ADB61A48E29E36bc873070A46A3D2667ff3`。它底層代幣的鑄造權只在發行方手上，所以除了發行方
沒人拿得到那個公開代幣，沒人包裝得出機密版本，也根本開不成池。

Hearth 還是把它列在池選單裡，反灰，旁邊寫上理由：`鑄造權限於發行方`。點它會開啟一個頁面，寫出
代幣名稱、把兩個合約連到 Etherscan、說明這是誰設下的限制，且不提供任何錢包操作，因為一顆按下去
就會失敗的存入按鈕，比沒有按鈕更糟。

把這個代幣從清單上拿掉會比較省事，但看起來會像 Hearth 只是還沒做到它。一位來找 tGBP 的存戶會看到
兩筆：一個可以用的 mock 池，和一個不能用的官方代幣，附上理由。

## App 從哪裡拿到位址

App 從來不帶手打的位址。`packages/web/src/lib/chain/pools.json` 裡的每一個開放中的池，都是從部署
腳本寫出的檔案產生的，指令是：

```
node scripts/sync-pools.mjs        # from packages/web
```

那支腳本會讀 `packages/contracts/deployments/sepolia/hearth.<slug>.json`，拒絕任何缺位址的檔案、
拒絕兩個池宣稱同一個代號，並補上那一筆沒有部署紀錄的受限項目。每次部署後都要跑一次。以前用來存
單一個池那三個位址的環境變數已經拿掉了。

存戶正在看的是哪個池，寫在 `/app` 後面的第一段：

| 路由 | 顯示什麼 |
| --- | --- |
| `/app` | 轉往存戶上次使用的池，第一次造訪則是 `usdc` |
| `/app/<slug>` | 該池的儀表板 |
| `/app/<slug>/deposit` | 該代幣的鑄造、遮蔽與存入 |
| `/app/<slug>/withdraw` | 該代幣的提領與解除遮蔽 |
| `/app/<slug>/draws` | 該池的各期抽獎，以及存戶自己在每一期的結果 |
| `/app/<slug>/run` | 該池那五個無需許可的抽獎步驟 |
| `/verify?pool=<slug>` | 該池的公開種子、級距與門檻 |

除了英文以外，每一種語言都會在這些路由前面加上語言代碼，所以日文讀者的儀表板是 `/ja/app/weth`。

## 一池一支 keeper

七個池就是七支 keeper 程序，各自用同一組助記詞的不同帳戶索引簽名，因為兩支程序共用一個帳戶會搶
同一個 nonce。對照表和 pm2 設定檔在 [keeper](../operations/keeper.md)。
