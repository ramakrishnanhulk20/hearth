# 為什麼這件事需要 Zama

任何宣稱自己需要某項技術的專案，都該套上這個測試：把那項技術刪掉，看看產品還活不活得下來。如果它
照樣能跑，那項技術只是裝飾。

## 把加密刪掉，就沒有產品了

全同態加密，通常簡稱 FHE，意思是直接在加密數字上做運算、產出加密的答案，全程不解密輸入。Zama 的
Protocol 把這件事帶到以太坊上：一份 Solidity 合約可以對它讀不到的數值做加法、比較和選擇。

把它從 Hearth 拿掉，剩下的是這些。

| Hearth 的組成 | 沒有 FHE 的話 |
| --- | --- |
| 你的餘額 | 一個公開數字。任何人都能替你的存款和中獎機率標價。 |
| 中獎判定 | 一次公開比較。它一跑完，結果所有人都看得到。 |
| 誰中了獎 | 公開，因為落進某人餘額裡的入帳金額是一個看得見的數字。 |
| 隨機種子 | 要嘛是一個有人事先看得到的公開數字，要嘛是一個有人可以挑的鏈下數字。 |
| 獎金入帳 | 對已被指認的中獎者做的公開轉帳。 |

你得到的就是 PoolTogether。PoolTogether 已經存在、能用，而且跑了好幾年。沒有理由重做一個。

Hearth 真正在賣的，是 PoolTogether 給不了的東西：一種抽獎儲蓄，你的餘額、你的中獎機率和你的中獎
結果只屬於你，而抽獎本身仍然可以被陌生人查核。這兩個性質在透明的鏈上是互相衝突的。加密運算是唯一
能同時滿足它們的東西，而 Zama 的 Protocol 是今天以太坊上唯一做得到的地方。

沒有部分版本。上表五列每一列都是核心承諾。把其中任何一列的加密拿掉，產品就在那一列失敗。

## 我們確實用到的那些組件

不是一句「建立在 Zama 上」就算。以下是清單，附上每一項替我們做了什麼。

### 加密整數

錢和權重用 `euint64`，資金池的總累加器用 `euint128`，比較的結果用 `ebool`。每位存戶的本金、獎金、
權重和入帳金額都是其中一種，每個層級的結轉金也是。我們在它們上面做的運算是 `FHE.add`、`FHE.sub`、
對公開數字的 `FHE.mul`、`FHE.min`、`FHE.gt`、`FHE.le`、`FHE.and` 和 `FHE.select`。

比較在這裡做的事不只是中獎判定。每期有五次加密比較，把資金池的總權重擺在它上次已知級距周圍的那些
2 的冪旁邊，而唯一離開加密世界的，是「五個裡面超過了幾個」這個小小的計數。這就是抽獎怎麼拿到一個
可以拿來跑的公開尺度，而總額本身從來沒有變成一個數字。

`FHE.select` 值得一提，因為它是整個設計得以成立的關鍵。它是一個條件被加密起來的 if 敘述：它回傳
兩個加密值中的一個，而鏈上分不出是哪一個。這就是中獎者和沒中的人怎麼產生一模一樣的交易。Hearth 裡
沒有任何地方對祕密做分支。

`FHE.fromExternal` 接收使用者在瀏覽器裡建立的加密值和它的證明，把它轉成合約可以使用的值。這就是
一筆存入金額怎麼從頭到尾都以加密形式抵達。

### ERC-7984，機密代幣標準

每個池的資產都是 Zama 的機密代幣之一，也就是包在一個普通 ERC-20 外面的 ERC-7984 包裝器：cUSDC、
cUSDT、cWETH、cBRON、cZAMA、ctGBP 或 cXAUt。它們裡面的餘額是加密值，不是公開數字。

存入透過 `confidentialTransferAndCall` 抵達，它在同一筆交易裡轉出一筆加密金額並呼叫接收方的 hook。
金庫的 hook 拿到的是代幣實際移動的金額，這就是金庫記的是現實、而不是一個請求的原因。給付則走另一個
方向，透過 `confidentialTransfer`。

用標準代幣、而不是自己寫一個，很重要。這個領域有好幾個專案自己手寫了「類 ERC-7984」的代幣。我們用的
每一個都是 Zama 部署的代幣，所以存戶的機密餘額在 Hearth 之外也用得到，而那個代幣自己的行為，不是
我們可以往對自己有利的方向定義的東西。這也表示 Zama 一發布新的機密代幣，Hearth 當天就能為它開一個
池，七個池裡有六個就是這樣加進來的；而對於發行方把鑄造權留給自己的代幣，它可以一個池都不開。

### 加密隨機性

`FHE.randEuint64()` 在 Zama 的協同處理器裡，以網路的 FHE 金鑰、從一個公開但沒有那把金鑰就毫無用處
的種子，生出一個隨機數。這個數字出來時是密文。沒有人看得到它被建立那一刻的值，包括我們，也包括
送出那筆交易的人。

它必須在一筆交易裡生成，因為它會改動鏈上的產生器狀態。這就排除了用 `eth_call` 在鏈下預覽一次抽獎、
看看自己會不會中的那個把戲，也是截止一期抽獎必須是一筆真交易、而且只會成功一次的原因。沒有人能把
不喜歡的種子重擲一次。

### 存取控制清單

Zama 的鏈上 ACL 決定誰可以解密哪一份密文。它是執行機制，不是政策：中繼器會拒絕呼叫者沒有被授權的
handle 的請求。

Hearth 在上面用四個呼叫。`FHE.allowThis` 讓一個值在後續交易裡仍然可以被合約使用。`FHE.allow` 給
存戶對自己的本金、獎金、逐期權重和逐期入帳金額的永久讀取權。`FHE.allowTransient` 只在一筆交易的
期間內授權，這就是金庫怎麼把一批評估總額的一次性額度交給資金池，而完全不給它常設權限。
`FHE.makePubliclyDecryptable` 把一個值對所有人打開，我們只在剛好六種值上使用它：種子、給出級距的
那個尺度計數、非空旗標、收成金額、某層級到期對帳時它的結轉金，以及未撥付計數器。資金池精確的總權重
刻意不在那份清單上。

最後那個呼叫是單向而且永久的。它是一份合約在這個協定上做得到的、後果最重大的一件事，所以 Hearth 裡
每一次使用都列在[什麼保持私密](../security/what-stays-private.md)。

### EIP-712 使用者解密

這是存戶怎麼讀自己的數字。他們簽署一則有型別的結構化訊息，那是一種會把「你到底在批准什麼」明白顯示
給簽署者看的簽章標準，然後 Zama 的中繼器把該存戶有權存取的那些值的明文回傳給他。

這是一個鏈下請求。沒有交易、沒有 gas、沒有痕跡。這就是 Hearth 可以完全不要領獎函式的原因：知道自己
中了獎不花任何成本，也不留下任何東西。這個承諾的另一半，是評估同樣沒辦法瞄準自己，所以根本不存在
一種「只有中獎者才會送」的交易。

餘額和獎金都可以被它們的擁有者解密。Hearth 另外還授權了逐期權重和逐期入帳金額，所以存戶可以拿自己
的輸入去驗證這一期的算術，而不是被要求信任它。

### KMS 簽章的公開解密

另一個方向。合約把一個值標成可公開解密，任何人向中繼器索取明文，中繼器連同金鑰管理服務（持有網路
解密金鑰的那一群人）的簽章一起回傳。合約在依那個數字行動之前，會先用 `FHE.checkSignatures` 在鏈上
驗證那個簽章。

這就是把「我們說種子是 12345」變成一個「合約自己在沒有證明時會拒收」的數字。Hearth 每期用它一次，
在開獎時一起處理種子、尺度計數、非空旗標和收成金額，而每當某層級到期對帳時，再為它的結轉金用一次；
在 Sepolia 上就是每期每個層級都用。每一份證明都以固定順序綁在它的那些 handle 上，所以沒有東西能被
調換順序，或被重放到另一期、另一個層級。

## 存戶實際上信任了什麼

把這件事點名，正是這一頁的目的。

- **Zama Protocol**，信任它在密文上正確運算，而且只解密被標為可解密的東西。合約會據以行動的每一次
  解密，都帶著在鏈上驗證過的證明。這跟 Zama 自己的機密金庫所記載的是同一條信任邊界。
- **機密代幣包裝器**，那是 Zama 的合約而不是我們的，而且它們的擁有者可以升級它們。見
  [什麼保持私密](../security/what-stays-private.md)的代幣層那一節。
- **Hearth 自己的合約**，它們一旦部署就不可變更，沒有代理，也沒有升級路徑。擁有者剩下的權力很窄，
  列在[威脅模型](../security/threat-model.md)裡：一個會停止存入和抽獎截止、但永遠不會停止提領或
  評估的暫停開關、一個收益來源設定器、一條碰不到存戶餘額的外來代幣救援路徑，以及一個關閉了放棄
  功能的兩階段所有權轉移。

這份清單上，沒有任何一項是我們要你去相信的某個人。
