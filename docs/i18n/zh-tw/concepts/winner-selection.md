# 中獎判定

這是整個產品的核心：在誰都讀不到的數字上決定誰中了獎，而且陌生人還是查核得了。

**最重要的一句話：中獎結果在開獎那一刻就定了，評估只是把它寫下來。** 資金池驗證完隨機種子和池子
總額所落的級距的那一瞬間，每位存戶在每個層級的結果就已經確定。門檻是任何人都能重算的公開數字，
而被拿來比較的加密權重也再不會變。評估只是記帳。它沒辦法被操縱、被搶跑，也沒辦法用略過的方式改變
誰中了獎。

## 開獎時被固定下來的東西

| 符號 | 是什麼 | 公開？ |
| --- | --- | --- |
| `R` | 這一期的隨機種子 | 是，該期結束之後 |
| `M` | 池子總權重落在的級距，一個 2 的冪 | 是，該期結束之後 |
| `prize[t]` | 層級 `t` 的一份獎付多少 | 是，截止時固定 |
| `offered[t]` | 層級 `t` 為這一期拿出來的資金 | 是，截止時固定 |
| `count[t]` | 層級 `t` 每期提供幾份獎 | 是，部署時固定 |
| `odds[t]` | 層級 `t` 多常派獎，以分數表示 | 是，部署時固定 |
| `W` | 該期資金池的時間加權餘額總和 | **否。永不公布** |
| `twab` | 某位存戶該期的時間加權餘額 | 否，加密，只有該存戶讀得到 |

最後兩列是祕密。`twab` 是個人的。`W` 是所有 `twab` 的總和，之所以留著不放，是因為精確公布它，等於
遞給旁觀者一個用減法還原落單者存入金額的方法。抽獎實際跑的對象是 `M`：大於或等於 `W` 的最小 2 的
冪。所以 `M` 落在 `W` 和 `2W` 之間，而旁觀者從一期到下一期唯一學到的，就是池子有沒有跨過一個 2 的
冪。

## PoolTogether 的規則，和我們的

PoolTogether V5 給每位存戶在層級 `t` 裡 `count[t]` 次獨立機會。每一次機會中獎的機率是
`min(1, twab * odds[t] / W)`。所以一位存戶在某層級的預期得獎數，等於他在池中的佔比，乘以該層級的
機率，再乘以獎項數量。

在加密數字上照字面做這件事，會需要為每位存戶的每一份獎抽一個新的隨機數，而且需要精確的 `W`。
Hearth 用「每位存戶每個層級一個均勻隨機數」加上一階巢狀門檻的階梯，並以 `M` 取代 `W`，重現了同樣
的形狀。

寫作 `z = twab * odds[t] * count[t] / M`。那就是這位存戶在這個層級的預期得獎數。Hearth 付給他們
`floor(z)` 或 `ceil(z)` 份獎，上限是 `count[t]`，而多期平均下來剛好就是 `z`。

因為分母是 `M` 而不是 `W`，每位存戶的期望值都被乘上 `W / M`，一個介於二分之一和一之間的數。把所有
存戶加起來，一個層級每期派出的獎，介於它名目上 `count * odds` 份的一半到全部之間。這樣不會損失
任何東西。層級沒派掉的部分留在它的加密結轉金裡，下一次截止時再拿出來，所以長期來看收益還是全部
發得出去；只是獎金金額會停在比較高的水位。見[獎金與層級](prizes-and-tiers.md)。

## 判定式，逐步拆解

對第 `p` 期抽獎中，層級 `t` 裡的存戶 `u`：

1. 導出他在這個層級的隨機數。`prn = keccak256(R, p, u, t)`。因為存戶的位址和層級索引都進了雜湊，
   所以每位存戶都拿到自己的數字，每個層級也各不相同，而全部都來自那唯一一個種子 `R`。
2. 把它縮進級距。`r = prn mod M`，一個從 `0` 到 `M - 1` 的整數。`M` 是 2 的冪，所以這只是一個
   256 位元雜湊對 2 的冪取餘數，剛好是均勻的，沒有偏差需要修正。這一步是公開值上的公開算術。
3. 造出階梯。對每一份獎 `k`，從 `0` 到 `count[t] - 1`：
   `threshold_k = floor((r + k * M) * oddsDen[t] / (oddsNum[t] * count[t]))`。
   這些都是公開數字。任何人都能為任何位址算出來，而合約把同一套算術以 view 函式
   `thresholdOf(drawId, saver, tier, k)` 公開，所以 App 的驗證面板、測試和任何外部查核者，用的都是
   同一份實作。
4. 比較。當存戶的加密權重大於 `threshold_k` 時，第 `k` 份獎就中了。這是唯一碰到祕密的一步，而它是
   一次加密比較，結果是一個沒人讀得到的加密 true 或 false。
5. 給付。每中一份獎，就把 `prize[t]` 加到該存戶在這個層級的加密給付上，做法是加密選擇而不是
   if 敘述，所以不管他們一份都沒中還是全中，交易看起來一模一樣。
6. 設限。該層級付給這位存戶的金額，取「他中了多少」和「該層級還剩多少」兩者中較小的一個。那次減法
   會更新該層級加密的剩餘資金。
7. 入帳。設限後的金額加到該存戶的加密獎金上。

門檻隨 `k` 遞增，所以一位存戶會中第 `0` 份到第 `j-1` 份獎，然後就停了。第 `k` 份獎的條件，正好是
`twab * odds * count > r + k * M`。

### 唯一一個明文分支

如果某個門檻大於 `2^64 - 1`，任何 64 位元的權重都不可能超過它，所以答案是 false，比較完全跳過。
這會發生在 `M` 非常大時的低機率層級上。既然門檻只會隨 `k` 遞增，該層級的迴圈就停在第一個這樣的
門檻，不再檢查後面的。這個分支是建立在公開數字上的。Hearth 從不對祕密做分支。

## 實例：三位存戶，一個層級

一個很小的池，好讓數字讀得懂。一個層級：常態獎層級，`count = 4`，`odds = 1`（也就是
`oddsNum = 1`、`oddsDen = 1`）。權重的單位是該池所持代幣的餘額秒；這個例子把它們讀成 USDC。

| 存戶 | 權重 | 佔 `W` 的比例 | `z = weight * 4 / M` |
| --- | --- | --- | --- |
| Ada | 600 | 60% | 2.34 |
| Ben | 300 | 30% | 1.17 |
| Cy | 100 | 10% | 0.39 |
| **總計 `W`** | **1,000** | 100% | **3.91** |

`W` 是 1,000，所以級距是 `M = 1,024`，也就是大於或等於它的最小 2 的冪。池子外面的人看不到那個
1,000。他們看到的是 1,024。

注意總計那一欄。這個層級名目上每期派出 `count * odds = 4` 份獎。它實際預期派出的是
`4 * W / M = 4 * 1000 / 1024 = 3.91`。那就是 `W / M` 的縮放，這裡是 2.3% 的折損，因為 1,000 靠近
它那個級距的上緣。一個總額 520 的池會落在同一個級距的下緣，該層級預期派出的會變成大約 2.03 份。

現在抽獎發生了。每位存戶的 `r` 來自把種子和他自己的位址一起雜湊，所以每個人都不一樣，落在 0 到
1,023 之間。

**Ada，`r = 271`。** 門檻是 `floor((271 + k * 1024) / 4)`：

| k | 門檻 | Ada 的權重 600 超過了嗎？ |
| --- | --- | --- |
| 0 | 67 | 是 |
| 1 | 323 | 是 |
| 2 | 579 | 是 |
| 3 | 835 | 否 |

Ada 中了 3 份獎。她的期望值是 2.34，所以 3 是 `floor` 和 `ceil` 中較高的那一邊。

**Ben，`r = 812`。** 門檻 `floor((812 + k * 1024) / 4)`：

| k | 門檻 | Ben 的權重 300 超過了嗎？ |
| --- | --- | --- |
| 0 | 203 | 是 |
| 1 | 459 | 否 |

Ben 中了 1 份獎，期望值是 1.17。

**Cy，`r = 155`。** 門檻 `floor((155 + k * 1024) / 4)`：

| k | 門檻 | Cy 的權重 100 超過了嗎？ |
| --- | --- | --- |
| 0 | 38 | 是 |
| 1 | 294 | 否 |

Cy 中了 1 份獎。他的期望值是 0.39，所以今天是他的好日子。長期下來，他大約 39% 的期數中一份獎，
其餘什麼都沒有。

預期派出 3.91 份的地方，實際派出了五份。這沒問題：每一份獎是該層級資金的八分之一，所以這個層級付
八份才會見底。見[超額中獎](prizes-and-tiers.md)。

現在來看看這一切結束後，旁觀者看到了什麼。他們可以自己把上面三張表全部算出來，因為 `R`、`M`、
門檻和位址都是公開的。他們做不到的是填上最右邊那一欄，因為權重是加密的；他們也還原不出那個 1,000，
因為公布的只有 1,024。該層級對帳後，也就是一期之後，他們會知道它派了幾份獎。他們永遠不會知道派給
了誰。

## 為什麼把錢包拆開沒有好處

這是做壞的版本會失去的性質。

一位存戶在某層級的預期得獎數是 `z = twab * odds * count / M`，它對權重是線性的，而 `M` 跟池子的
權重怎麼分配在各位址之間無關。把 600 的權重拆成兩個各 300 的錢包，每個拿到 `z = 1.17`，合計 2.34。
一模一樣。拆成六個各 100 的錢包，每個拿到 0.39，合計 2.34。又是一模一樣。沒有門檻可以鑽，也沒有
進位可以刷，只有更多 gas 要付。

這個設計的早期版本把獎項數量摺進單一個更寬的中獎區間，所以每位存戶在每個層級最多只能中一份獎。
那讓大額持有者拿到低於應得份額的東西，還變相獎勵拆錢包。一次設計審查抓到了它，改成現在的巢狀階梯。

## 它的成本

每位存戶每期的加密運算是：一次乘法和一次加法算出權重，然後每個層級的每一份獎各一次比較和一次選擇，
再加上一次設限。以 Sepolia 上的三個層級來說，那是 6 次比較、6 次選擇，加上大約十來次加、減和取
最小值。

Zama 公布 Sepolia 上單筆交易的預算是總共 20,000,000 個運算單位，其中循序深度 5,000,000，並把
64 位元加法標價為 162,000、比較約 118,000、選擇 55,000、乘以公開數字 365,000。這些數字讓一位存戶
落在數百萬個運算單位的水準，這也是評估要以每筆交易 `4` 位存戶批次處理的原因。實測數字是每位存戶
`3,674,128 on the mock coprocessor's price table (the live coprocessor does not report compute units in a receipt)`，實測 gas 是 `708,836 (the marginal cost of one more saver in a batch; a batch of one costs 1,291,192)`。

## 這一頁沒有講到的

它沒有講 `R` 從哪裡來或怎麼驗證，那是[隨機性與驗證](../security/randomness-and-verification.md)。
它沒有講 `prize[t]` 的金額怎麼定、或某層級在抽獎中途派完了會怎樣，那是
[獎金與層級](prizes-and-tiers.md)。而且它完全沒有宣稱能隱藏誰參與了：存戶名單、各批評估和各層級的
獎項數量都是公開的。見[什麼保持私密](../security/what-stays-private.md)。
