# 什麼保持私密

關於機密性，有三件事重要：什麼保持加密、抽獎是否可證明公平且依存款加權，以及每一處外洩是否都被
點名。這一頁回答第一和第三個。我們的立場是：自己把每一道接縫都講清楚，比一個沒人查得了的宣稱更有
價值。

這裡寫的一切都是針對單一個池，而 Hearth 跑七個，每種機密代幣一個。它們什麼都不共用，所以每個池的
匿名集合就是它自己的存戶，不包含任何別人，而一個只有三位存戶的池，不會因為另一個池有三十位就變安全。

## 那張表

| 數值 | 狀態 | 誰讀得到 |
| --- | --- | --- |
| 你的本金 | 加密 | 只有你，透過 EIP-712 簽章 |
| 你未領取的獎金 | 加密 | 只有你 |
| 你逐期的時間加權權重 | 加密 | 只有你 |
| 你逐期的入帳金額，因此也包括你有沒有中獎 | 加密 | 只有你 |
| 你存入的金額 | 全程加密 | 只有你 |
| 你提領的金額 | 全程加密 | 只有你 |
| **該期資金池的總權重** | **加密，永不公布** | **沒有人** |
| 各層級在兩次對帳之間的結轉金 | 加密 | 沒有人 |
| 資金池總額落在的級距，一個 2 的冪 | 該期結束後公開 | 所有人 |
| 該期到底有沒有人持有餘額 | 該期結束後公開 | 所有人 |
| 每期的隨機種子 | 該期結束後公開 | 所有人 |
| 每期收成的收益 | 該期結束後公開 | 所有人 |
| 各層級的獎金金額和拿出來的明文資金 | 從截止起公開 | 所有人 |
| 常態獎層級派了幾份獎 | 一期之後公開 | 所有人 |
| 中型獎層級派了幾份獎 | 一期之後公開 | 所有人 |
| 頭獎層級派了幾份獎 | 一期之後公開 | 所有人 |
| 存戶位址清單 | 公開 | 所有人 |
| 你在什麼時候存入、提領或被評估，以及在哪一批 | 公開 | 所有人 |
| 未撥付計數器 | 定案時公開 | 所有人 |
| 贊助金額和滴出速率 | 公開 | 所有人 |
| 你包裝進機密代幣、或從中解除包裝的金額 | 公開 | 所有人 |
| 任一位址在任一層級必須超過的每一個門檻 | 可公開計算 | 所有人 |

那張表有兩種讀法。左邊那一欄祕密，恰好就是個人層級的資訊，加上那兩個結果發現是「個人資訊喬裝的」
全池總額。右邊那一欄公開事實，則是外部人查核這次抽獎是否誠實所需要的東西。這個切分就是設計本身。

## 旁觀者算得出什麼、算不出什麼

一個有完整封存節點和無限耐心的旁觀者，可以建出：

- 完整的存戶名單，以及每個人動作的確切區塊。
- 每一期的種子、級距、收成和獎金金額，以及各層級的獎項數量（在它所屬那一期之後一期）。
- 每個位址必須超過的每一個門檻。他們真的算得出你的那道階梯。
- 資金池所持機密代幣的總量，形式是一個他們讀不懂的加密 handle。

他們拿不到：

- 任何時刻的任何個人餘額。
- 任何個人的權重，因此也拿不到任何個人的中獎機率。
- 任何一期是哪些位址中獎，或誰被付了多少。
- 資金池精確的總權重，只有它上方的那個 2 的冪。

這兩份清單之間的落差，就是 Hearth 在賣的東西。這一頁剩下的部分，是關於那個落差在哪裡變窄的誠實
交代。

## 規則 1：級距，以及我們移除掉的那個外洩

直到 2026 年 9 月 3 日為止，這個設計每期都公布資金池精確的時間加權餘額總和 `W`，理由是公布它才讓
抽獎可驗證。一次審查證明那個理由代價太高。

用審查者的話說，外洩長這樣。對任何已截止的第 `p` 期，
`W_p = B * L + sum over each action of D_i * (periodEnd(p) - t_i)`，其中 `B` 是帶進該期的本金總額，
`D_i` 是每個動作造成的帶號變動量。`B`、`L`、`periodEnd(p)` 和每一個 `t_i` 都是公開的，因為存入和
提領事件都帶著時間戳。所以**一位在某期唯一動過錢的存戶，他的金額可以從兩次公布的總額和他自己那筆
交易的公開時間戳裡還原出來。** 不是推估範圍，是精確還原，餘數為零。資料愈多只會愈糟不會愈好：每一
個結束的期就是一條方程式，每一個動作就是一個未知數，這條鏈錨定在零，而事件會寫出誰動了、何時動的，
所以兩段安靜期之間的兩位動作者，同樣會被精確還原。

那個外洩沒有了，因為它需要的數字不再被公布。金庫現在公布的是級距：大於或等於 `W` 的最小 2 的冪，
寫作 `M`。每期五次加密比較，追蹤 `W` 相對於上一期級距落在哪裡，而只有它們加總出來的那個小計數會
被解密。在兩次跨越 2 的冪之間，相鄰的期會公布同一個數字，相減得零。

留下來的，是同一件事情弱很多的版本。

- **一位存戶。** 公布的級距就是這位存戶的權重，誤差在兩倍以內。
- **兩位存戶。** 各自可以減掉自己的權重，把對方的推估在兩倍以內。
- **三位以上。** 任何跟級距相容的分法都有可能，而這個集合會隨著每多一位存戶而變大。

只要池裡不到三位存戶，App 就會在每個畫面上方寫明這件事。Zama 自己的文件用同樣的字眼，對他們的
批次器講了同一個重點：「一個值的總和就是那個值。」級距是那句話的弱化版，不是它的逃生口。

## 規則 2：一個旁觀者鎖定得了的餘額，在抽獎上完全沒有隱私

這是整頁最尖銳的一句話，所以它自己占一條規則。

中獎判定是一個確定性函數，輸入只有一個祕密（你的權重），其餘全是公開資料。門檻依設計就是公開的，
因為那正是讓抽獎可查核的東西。所以**任何能鎖定你餘額的人，完全不需要解密，就能算出你在每一期、
每一個層級是中是沒中**，而且從此以後每一期都算得出來，因為獎金放在一個獨立的餘額裡，永遠不會進入
中獎機率的計算。

餘額被鎖定最常見的方式，就是規則 3 講的包裝接縫：把公開代幣換成機密形式是一次公開的移動，所以一位
包裝之後幾秒鐘就存入同樣金額的存戶，等於把他的存入金額公布了。從那一刻起，他的抽獎結果就是公開的
算術。

就算只有一個寬鬆的界線也咬得住。一個只握有你餘額上界的旁觀者，就能證明你在任何門檻高過那個界線的
層級裡確定沒中。

App 對此做了什麼：把遮蔽和存入保持成存入畫面上的兩個獨立步驟，並在遮蔽那一步用一段話告訴你，用整數
金額，讓一次遮蔽變成一個桶子而不是一筆精確的存入；在你自己挑的時間點遮蔽；之後再撥一部分存入，讓
一筆存入來自一個組成成分未知的累積。沒有任何合約改動做得到的，是把門檻變成私密的，因為私密的門檻
就是一場查不了的抽獎。

## 規則 3：包裝接縫，兩個方向

把公開代幣變成它的機密形式，是一次公開的 ERC-20 移動。這個金額會出現在包裝器的 `Wrap` 事件裡、出現
在底層代幣的 `Transfer` 裡，並在協同處理器加密那份明文的紀錄裡再出現一次。把公開代幣轉過去，沒有
任何機密的做法。

我們在自己早期的部署上量過這個關聯。掃描 Sepolia 第 11528000 到 11618500 區塊，五筆存入中有三筆
落在同一個位址公開包裝整整 100 USDC 之後的兩到四個區塊。任何讀公開日誌的人，都能把那三筆存入標價
成 100 USDC，完全不需要突破任何一個密碼學保證。Zama 為他們的批次器記載了同樣的效應，稱之為
shield-join 關聯。

解除包裝同樣會公布一個金額，而且是兩個 unwrap 呼叫中的第一個在公布，所以一筆從未完成的 unwrap 照樣
洩漏。這帶出第二個被點名的揭露：**對於全額包裝進來、又全額解除包裝出去的位址，累積獎金會變成一個
公開的下限。** 對一個在該機密代幣上唯一交易對手就是 Hearth 的位址來說，公開的解除包裝總額減去公開
的包裝總額，恰好就是「歷來已提領的中獎金額」，再扣掉該位址仍持有的本金和機密餘額。那兩者都是隱藏
的、而且非負，所以這個差額永遠是下限，並在該位址把錢清空之後變成精確值。

換到一個全新位址再解除包裝也沒有用，因為轉到那個位址的機密轉帳本身就是那條連結。

Hearth 做了什麼：拆成獨立步驟、在存入的遮蔽步驟放上警語、在那一步以及提領的「換回一般 USDC」分頁
各放一行字，告訴你動整數金額，並建議你留一筆常駐的機密餘額。金額怎麼填終究是你的事；App 不提供一組
固定面額。Hearth 做不到的是：把這些消掉任何一項。

## 規則 4：公布的獎項數量是一種緩慢的測量

每次對帳都會公布某層級派了幾份獎。因為每位存戶的門檻都是公開的，那個數量就是一條硬約束，形式是
「這些存戶裡有幾位的權重高過他們自己那個公開的門檻」。它只帶幾個位元的資訊，但它是一次真實的測量，
而且會累積。

**一個跨越很多期都不變的餘額，會被那些數量逐步縮小範圍。** 而一位存入或提領的存戶會重置自己的未知
數，讓縮小的過程從頭來過。

有兩件事限制了它的速度。這些數量很粗糙：揭露的東西永遠不會比「整數份獎」更細。而且門檻不是攻擊者
可以選的，因為種子是在協同處理器裡抽的，要等它那一期結束後才揭露，所以沒有人能把查詢瞄準一個被
懷疑的餘額。

還有第三種阻尼是可以用的，而這次部署刻意放棄了它。`reconcileEvery[t]` 設定一個層級兩次公布結轉金
之間隔幾期。把它調高，會變成一段期間公布一個數量，而不是每期一個，所以一次頭獎會被歸給那段期間內
所有有資格的人。它的代價是頭獎本身：一次截止會把一個層級全部的公開資金移進該期抽獎，而那筆錢只有在
對帳時才回來，所以在節奏為 24 的情況下，24 期裡有 23 期，頭獎層級的公開資金就只是一期的收成份額，
公布的獎金金額照那個算，而累積起來的獎池只在對帳那一期才出現在檯面上。那筆錢全程都在加密結轉金裡
被拿出來、也贏得到。只是沒有人看得見它。

所以三個層級全都跑在 `reconcileEvery = 1`。獎池在公開狀態下累積，每個層級的數量在一期之後變公開，
而上面那個測量也就以每個層級每期一個數量的全速在跑。在頭獎層級上，這表示一次派獎指向的是該期有資格
的那些存戶，大約是池子的 4%，而不是一整天份的存戶。這是一個已揭露的殘留風險，不是已緩解的，它是
限制 14。這個節奏仍然是建構子參數，所以想要比較慢的測量、勝過想要看得見的獎池的部署，隨時可以那樣做。

## 規則 5：代幣層是 Zama 的，不是我們的

每個池的資產都是 Zama 的機密代幣之一。這是刻意的，也意味著那個代幣自己的權力，適用於流經 Hearth
的錢，一池一池都算：七個包裝器，每個都有同一組權力。把它們點名：

Sepolia 上那份合約是一個放在可升級代理後面的 `ConfidentialWrapper`，由 Zama 擁有，採兩階段所有權
且關閉了放棄功能。在 2026 年 9 月 2 日讀它經過驗證的原始碼，得到三個對隱私有影響的事實：

1. **觀察者，而且可回溯。** 擁有者可以呼叫 `addObserver(address)`，讓該位址對代幣合約握有權限的
   每一個 handle 都取得萬用的使用者解密權。那涵蓋每一筆存入金額、每一筆提領給付，以及資金池送給
   金庫的每一批獎金撥款金額。關鍵字是可回溯：一個未來任何時間被指派的觀察者，都能解密已經在鏈上的
   金額，所以「盯著 `ObserverAdded` 然後退出」不構成防禦。2026 年 9 月 2 日的線上狀態：
   `observerCount()` 是 0，`observers()` 是空的。
2. **拒絕名單與暫停。** 擁有者可以封鎖一個位址，讓它無法存入、提領或解除包裝，因為這三件事各自都是
   一次有該位址在其中一側的代幣更新。有一個暫停者角色；線上它被設成零位址，所以暫停目前是關閉的。
3. **可升級性。** 實作可以被它的擁有者換掉，所以代幣的行為，包括它怎麼處理自己握有權限的那些
   handle，都可能在我們腳下改變。

注意第 1 項的精確範圍。Hearth 裡沒有逐人的獎金轉帳，所以沒有逐個中獎者的給付可以讓觀察者去讀。在
代幣層移動的，是每批評估一筆的撥款轉帳，從資金池到金庫，帶著那一批裡所有人的入帳總額。一批只有
一個人時，那個總額就是該存戶的精確獎金，而線上那個五位存戶、批次大小為 4 的池，每次巡走結束時的
最後一批都只有一個人。`evaluate` 無需許可，批次大小由呼叫者決定，所以沒辦法強制一個最小批次。
[限制 7](../limitations.md) 把它記為一個被接受的殘留風險，並點出合約端的修法。

代幣層的觀察者拿不到的，是 Hearth 自己的帳本。你的本金、你的獎金、你的權重和你的入帳金額都活在金庫
的儲存空間裡，而代幣對它們一項存取權都沒有。我們在前一版部署上驗證過：代幣位址對某位存款人的獎金和
本金 handle 查詢權限時回傳 false，而該存款人和資金池回傳 true。

所以誠實的說法是：使用 Hearth，你把「經過它的那些金額」交給 Zama 的包裝器去信任，跟任何一個
ERC-7984 應用完全一樣。你並沒有把自己的部位交給它。

另一個選項是自己寫一個機密代幣，這個領域有好幾個專案就是那樣做的。那等於拿一份已知、經過稽核、由
Zama 營運的合約，去換一份要我們自己給自己打分數的合約。我們寧願把真正的信任邊界寫清楚，也不要製造
一個看起來比較小的。

## 規則 6：評估不會洩底，而且沒有人能選順序

`evaluate(drawId, count)` 收的是一個數字，不是一份位址清單。金庫從該期種子導出的起點開始，照名單
順序走過存戶名單，呼叫者只決定要往前推進多遠。想知道自己結果的存戶，推進的是跟 keeper 同一條巡走。

這一下堵住兩件事。

它堵住了「自我評估」這個洩底。在早期版本裡，評估收的是一份位址清單，所以存戶可以從公開輸入算出自己
的結果，然後只在中獎時才付錢去被評估。送出那筆交易，會跟一個領獎函式一樣大聲地洩漏中獎者身分。
現在根本不存在一種「只有中獎者才會送」的交易。

它也堵住了順序這根槓桿。當某層級超額中獎而見底時，巡走最後走到的人會短少。那個順序由種子固定，所以
沒有人能用 gas 買到比較好的位置，而且起點每期都會移動，所以沒有哪個位址會系統性地排在最後。它在
公平性上的後果寫在[獎金與層級](../concepts/prizes-and-tiers.md)，也就是限制 11。

某一期裡被評估的每位存戶，都拿到同樣的、同樣形狀的寫入，不管中沒中獎，因為給付走的是加密選擇而不是
分支。一位存戶落在哪一批、在批裡的位置，都是公開的，而且完全說明不了他的結果。

## 規則 7：行為上的殘留線索

Hearth 沒有領獎交易，所以沒有一個「中獎者形狀」的動作可以盯。知道自己中了獎是一個什麼都不碰的鏈下
簽章，而 App 上那顆標著金額的領獎按鈕，送出的是一筆跟其他每一筆提領長得一樣的普通提領。

殘留的是你接下來做什麼。一位每次中獎後就馬上提領、其他時候從不提領的存戶，長期下來會遞給旁觀者一個
統計線索。它很弱，要累積很多期才成形，而且完全在存戶自己的控制之下。緩解方式是行為上的，不是密碼學
上的：照你自己的節奏提領，或者讓獎金累積著。

我們把這件事寫出來，是因為另一種說法，也就是宣稱鏈上行為什麼都不透露，在這一類的每一種設計裡都是
假的。這個領域裡拿掉領獎函式的專案得到了同樣的結論，也把它寫了下來。我們也一樣。

## 這一頁沒有講到的

它沒有講攻擊者和他們的動機，那是[威脅模型](threat-model.md)。它沒有講你自己怎麼查核一期抽獎，那是
[隨機性與驗證](randomness-and-verification.md)。而且它對網路層級的隱私不做任何宣稱：你連線用的 IP
位址、你用的 RPC 服務商，以及你送出的中繼器請求，都在鏈之外，也在這份分析之外。
